# 问剑 · 论剑

> 原创武侠策略卡牌对战 demo —— 论剑 PvP（Bo5 暗置博弈）+ 爬塔 PvE + 抽卡保底，配固定 seed 可复现的蒙特卡洛平衡模拟器。
> 个人独立项目：数值设计 → 规则引擎 → 模拟验证 → 调参定稿的完整流程。

## 项目简介

《问剑·论剑》是一款双人策略卡牌对战游戏：双方在**信息不完全**（盖牌布阵、暗置指令）下进行 Bo5 论剑，核心是一套 AP 利息制经济与三率判定体系。项目的差异化不在"做出了游戏"，而在于**所有平衡结论都由可复现的模拟实验支撑**：模拟器直接复用线上规则引擎（规则即真相），固定种子逐字节可复现，关键实验 2 万局并报 95% 置信区间，全部调参决策留有数据案底（见 `sim/REPORT.md`）。

## 玩法速览

### ⚔️ 论剑 PvP（核心模式）

- **Bo5 × 大局套三小轮**：大局是资源重置单元（气血/内力重置、AP 按利息结存），小轮是信息递进单元；封盘走"存活数 → 伤害量 → 平轮"层级结算。
- **AP 利息制经济**：每大局发 8 AP，对 3 人 × 3 小轮 = 9 个行动槽的故意缺口；未用 AP ×1.5 利息结存、上限 20——"挂机攒点/让二追三"是合法但不统治的策略。
- **盖牌即站位**：布阵全暗置（人物 + 位置 + 绑定卡），锁阵后翻牌公开；策略卡（叫阵/拆招/掣肘/金疮药/移形/节流）、判定卡（乘势/稳军/孤注/神机妙算）、法器（跨大局培养线，适配 +20%/不适配减半）。
- **三率判定树**：神妙 → 擦碰 → 致命 → 命中，溢出率值按 0.6 系数转化为爆伤；1 AP ≈ 一次普攻 ≈ 154 期望伤害是全部定价的锚点。
- **两种对战方式**：房间码联网对战（服务端权威）+ 同屏双人幕布模式（HotSeat，无需后端）。

### 🗼 爬塔 PvE

- 气血几何增长曲线（1~10 层 ×1.22，第 11 层起软着陆防通胀失控）；第 3 层起普通层 35% 概率刷精英词缀（荆棘/狂暴/坚韧/迅捷）。
- 每 5 层头领战：Boss 气血跌破 50% 进入「困兽」阶段（攻击 ×1.4、受伤 +15%），制造斩杀窗口博弈；每 10 层大关底带护卫小怪逼转火决策。
- 三选一奇遇事件：稳妥项收益温和、激进项带真实代价。
- 全部数值集中在 `src/game/config.ts` 一张参数配表（改表即调参、不动代码的工作流）。

### 🌟 升星系统与抽卡

- **升星 = 绝技质变 + 小面板**：摸到对子可合 2★（绝技 Lv2 + 面板 +5%），三条合 3★（绝技 Lv3 + 面板 +10%、少上 1 人）——纯面板升星经模拟证明无定价解后改走此路线。
- **抽卡保底**：软保底递增 + 硬保底封顶 + 10 抽小保底；游戏内实机运行蒙特卡洛模拟（5 万玩家），向玩家公示 5★ 期望成本分布。

## 技术栈与架构亮点

**技术栈**：React 19 + TypeScript + Vite 7 + Tailwind CSS + shadcn/ui（前端）；tRPC 11 + Hono + Drizzle ORM + MySQL（后端）；Vitest（测试）；Node 20。

**架构决策**：

- **规则即真相**：`contracts/game.ts`（约 780 行纯函数 + 纯 JSON 状态模块）是唯一规则实现，前端同屏模式、服务端联网对战、蒙特卡洛模拟器三方共用同一份代码——规则改一行，三处同时生效，不存在"模拟规则与线上规则两份实现"的漂移风险。
- **服务端权威 + clientView 信息隐藏**：客户端只提交意图，全部判定在服务端执行；`clientView` 按身份脱敏（对方手牌打码、未翻牌只暴露"已盖牌"事实、暂存盖牌字段物理删除）——网络上根本不存在对方不该看到的数据。
- **可复现模拟器**（`sim/`）：每组实验固定 `mulberry32(seed)` 替换 `Math.random`，座位对半互换消位置偏差，结果落盘 `sim/results/*.json`；AI 机器人只读 `clientView`（与真人相同的信息集）。
- **实验设计纪律**：A/A 镜像基线校准（50.9%±0.7，2 万局）先行、单变量变体扫描、对照组隔离单卡边际价值、判定标准（±3pp）先于实验定。

## 快速开始

```bash
npm install        # 安装依赖（Node 20+）
npm run dev        # 开发模式（Vite + Hono dev server）
```

联网对战模式需要 MySQL：

```bash
cp .env.example .env   # 填入 DATABASE_URL 等
npm run db:push        # 推送数据库 schema
npm run dev
```

同屏双人模式（HotSeat）与爬塔 PvE 纯本地运行，无需数据库。

```bash
npm run build && npm start   # 生产构建并启动
npm test                     # Vitest（含模拟器冒烟与可复现性用例）
npm run check                # tsc -b 类型检查
```

### 跑平衡模拟

```bash
npm run sim -- anchors   # 任务1·锚点回归（镜像组 2 万局，其余 5000 局）
npm run sim -- thrift    # 任务2·节流银行流全参数扫描（定稿组 2 万局）
npm run sim -- stars     # 任务3·升星绝技强化（每侠客 2 万局）
npm run sim -- extras    # 锚点超差查因的补充实验（含全肉剂量-反应曲线）
npm run sim -- all       # 全部复现
```

结果写入 `sim/results/*.json`，与 `sim/REPORT.md` 中的数字逐一对得上（同一 seed 重跑逐字节一致）。

```

  ├─ pages/         论剑（Online / HotSeat）、爬塔 Battle、抽卡 Gacha、玩法说明页等

  └─ components/    shadcn/ui 组件与游戏组件
```

## 模拟结论摘要（详见 `sim/REPORT.md`）

- **节流银行流定稿**：apCarryThrift=2 / apCap=20，2 万局 **49.2%±0.7**，平衡带中心；AP 上限抬 24 则节流边际 +16~21pp 过强——上限 20 是利率的保险丝。
- **升星定稿**：六侠客合成胜率 **47.4%~52.3%**（2 万局/侠客）全部落入 45~55% 平衡带，有无对子的条件胜率差 ≤3pp——合成是"风格变体"而非最优解。
- **全肉偏强与剂量-反应**：全肉 vs 均衡实测 67.3% 超标；坦克攻击削减的剂量-反应曲线显示字面 −15% 不够（62.3%），需 −23.5%/−25.4% 深度削减才回到 ≈54%/**51.2%**（135~203 → 115~173/112~168）。
- **锚点回归的诚实结论**：11 项历史锚点严格通过 4 项（±3pp 线）、方向与量级同时一致 6 项；叫阵/法器/换位与历史方向相反、乘势量级超差，全部逐项归因到 AI 基线打法差异而非引擎错误——**模拟结论 = 规则 × 基线打法**，基线敏感卡全部进观察名单并预埋回调方案。

## 诚实声明

- 这是**独立个人项目 demo**，可一键构建运行（本地/预览环境），不是商业上线运营项目，无真实玩家数据。
- 全部平衡结论来自 AI 机器人模拟，正确口径是"**在该打法分布下**"：报告中的 v4 基线为"紧打"打法（AP 全转化、按击杀次数集火、斩杀式绝技闸门），真实玩家环境下的精细定档需以上线数据复核——这是本项目最重要的方法论结论，而非掩饰。
